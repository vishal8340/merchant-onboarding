🚨   MULTI-LAYER DUPLICATE MERCHANT GUARD — NEW in v9
Layer 1 — Real-Time Validation
POST /api/validate-merchant
Called at Step 1→2 transition (businessName) and on final submit (all fields).
No application record created. Returns isDuplicate + duplicateFields[].
Shows inline 2-line amber error banner. Blocks Next / Submit buttons.
Layer 2 — Application Creation Guard
POST /api/applications
Checks APPROVED merchants before inserting DRAFT record.
Returns HTTP 409 MERCHANT_ALREADY_ACTIVE if match found.
Frontend maps 409 to inline error + resets to offending step.
Layer 3 — Document Upload Page
GET /api/applications/:id/duplicate-check
Called on page load of Upload Documents screen.
Sets blocking overlay modal — user cannot upload or submit.
Helper: checkDuplicateForApp(appId) excludes self.
Layer 4 — Pre-Textract Submit Guard
POST /api/applications/:id/submit
Final check before Textract runs & agents are invoked.
Blocks submission even if layers 1–3 were bypassed.
Returns HTTP 409 — prevents duplicate from entering pipeline.
📌   End-to-End Request Flow (14 Steps)
1
User logs in → POST /auth/login → bcrypt.compare (rounds 12) → JWT issued (8 h) → stored in AuthContext → ProtectedRoute guards all views
⛔
GUARD L1: User fills Step 1 → clicks Next → POST /api/validate-merchant {businessName} → if APPROVED match found: inline error shown, step blocked
2
User completes Step 2 → clicks Submit → POST /api/validate-merchant {businessName, email, phone} → no duplicate → POST /api/applications → saved as DRAFT in MongoDB
⛔
GUARD L2: POST /api/applications re-checks APPROVED merchants on server side → returns HTTP 409 on match → frontend shows inline error + resets to offending step
3
User navigates to Upload Documents → page loads → GET /api/applications/:id/duplicate-check → if duplicate: blocking modal overlay appears, upload disabled
4
User uploads documents → POST /api/applications/:id/documents → Multer saves to /uploads/ → PDF→PNG via Ghostscript (200 DPI) → EPAM AI DIAL validates doc type (GPT-4o) → 422 on mismatch
⛔
GUARD L4: User clicks Submit → POST /api/applications/:id/submit → final server-side duplicate check before Textract runs → HTTP 409 if match → no pipeline invoked
5
Submit accepted → status → SUBMITTED · AWS Textract AnalyzeDocument (FORMS) called per PNG via Promise.all() — all documents in parallel → key-value pairs extracted
6
Orchestrator publishes 3 parallel messages: agent.kyc, agent.mcc, agent.risk to RabbitMQ :5673 (Homebrew). If RabbitMQ unavailable → direct in-process fallback via registerDirectAgents() · status → PROCESSING
7
KYC Agent consumes kyc.verification → cross-validates Textract KV vs. form → if score ≥ 85 & all checks pass: skips DIAL (~60% apps); else calls EPAM AI DIAL (GPT-4o) → publishes result.kyc
8
MCC Agent consumes mcc.categorization → calls MCC Analyser :8091 (LangChain4j RAG + gpt-4o-mini + ConcurrentHashMap cache) with 3 retries + exp. backoff → if RAG conf ≥ 0.6: skips DIAL (~85% apps); else EPAM DIAL fallback → publishes result.mcc
9
Risk Agent consumes risk.assessment → country/fraud flags → Step 1: Smart Risk Scoring :8080 (Weka RandomForest + LIME) always runs → Step 2: if LOW/MEDIUM risk: skips DIAL (~70% apps); if HIGH/MANUAL_REVIEW: calls EPAM AI DIAL (GPT-4o) → publishes result.risk
10
Orchestrator collects all 3 results → makeDecision() → APPROVED, REJECTED, or MANUAL_REVIEW · Telemetry recorded (tokens, latency, cost) per call
11
If AUTO APPROVED → generateMerchantCredentials() → Merchant ID (MID-XXXX…) + 12-char password stored · findOneAndUpdate() persists final state
12
Frontend polls GET /api/applications/:id with exponential backoff (starts 3 s, doubles, caps at 30 s) → stops on terminal status · TelemetryDashboard auto-refreshes every 15 s
13
If MANUAL_REVIEW → ReviewConsole queries GET .../review/pending → admin enters decision → POST .../:id/review → APPROVED (MID generated) or REJECTED
14
Approved merchant views POST .../:id/credentials → returns merchantId + merchantPassword only if APPROVED · HTTP 400 otherwise · Credentials never regenerated

🔄   Application Status State Machine
⛔ BLOCKED (dup)  |  DRAFT → SUBMITTED → PROCESSING →
✓ APPROVED ⚠ MANUAL_REVIEW  →  APPROVED / REJECTED ✗ REJECTED
Duplicate guard: Fires at Step 1→2, Step 2 submit, DRAFT creation, doc-upload load, and pre-Textract submit. Checks APPROVED collection only.  |  EventBus: If RabbitMQ :5673 unavailable → direct in-process agent execution via registerDirectAgents() — system remains fully functional.  |  Decision rules:  All scores ≥ 85 & no reviewRequired → AUTO APPROVED (MID + password generated immediately)  |  Any score 50–84 or reviewRequired=true → MANUAL_REVIEW  |  Any agent FAILED or score < 50 → REJECTED (no credentials ever generated)
