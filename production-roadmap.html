01   Critical Gaps — Block Production Launch
🚨
No Real Identity / Business Verification
KYC Agent validates form fields only — never confirms a business or person actually exists
BLOCKER
Current
Cross-validates Textract key-value pairs with form fields. Checks email domain, phone format. No external lookup.
Required
Biometric liveness check + government ID scan via Onfido / Jumio / Sumsub. Company registry lookup (Companies House, MCA, Bureau van Dijk Orbis). GLEIF LEI Registry for B2B. eKYC compliant with eIDAS (EU) / RBI KYC (India) / FinCEN (US).
🚨
No Sanctions / AML / PEP Screening
Non-negotiable for any payment acquirer or financial institution — regulatory requirement in every jurisdiction
BLOCKER
Current
Risk Agent scans for fraud keywords (gambling, crypto) and checks country risk flags. Rule-based only.
Required
Real-time screening against OFAC SDN list, UN Consolidated Sanctions, EU Consolidated List, PEP (Politically Exposed Persons) databases via ComplyAdvantage, Refinitiv World-Check, or Dow Jones Risk & Compliance. Auto-file SAR (Suspicious Activity Report) on matches. Must run on every onboarding and periodically on existing merchants.
🚨
PII Stored Unencrypted
GDPR · PCI-DSS · SOC 2 violation — TaxIDs, document content, names in plaintext
BLOCKER
Current
Files in /backend/uploads/ on local disk. Textract output (containing TaxIDs, names) written to /tmp/*.log. MongoDB stores all fields in plaintext.
Required
Documents in encrypted S3 / Azure Blob with SSE-KMS and access logging. MongoDB field-level encryption (CSFLE) for PII fields. PII masking in all logs. Secrets in AWS Secrets Manager / HashiCorp Vault — not .env files.
🚨
No TLS Between Services
All internal HTTP calls are plain — man-in-the-middle risk on backend → Java services
BLOCKER
Current
Backend calls http://localhost:8091 and http://localhost:8080 over plain HTTP. No service-to-service authentication.
Required
TLS on all service endpoints. mTLS between microservices (mutual certificate authentication). API gateway with rate limiting, auth, and WAF in front of all external-facing endpoints.
🚨
No Maker-Checker Workflow
Single admin can approve/reject alone — dual control is a regulatory requirement for payment acquirers
BLOCKER
Current
Any user with ADMIN role can approve or reject a merchant application from the Review Console without a second approver.
Required
4-eyes principle: reviewer flags → senior approver confirms. Segregation of duties enforced at API level. Approval chain configurable by risk level (LOW = 1 approver, HIGH = 2 + compliance officer). Full immutable audit trail per GDPR Article 30.
🚨
No Data Persistence Guarantees
Single-node MongoDB — one crash loses all application data
BLOCKER
Current
Single MongoDB instance on localhost. In-memory Map<id,app> fallback is lost on restart. RabbitMQ in Homebrew with no persistence config.
Required
MongoDB Atlas M10+ (3-node replica set, automated backups, point-in-time recovery). RabbitMQ cluster (3 nodes) with durable queues and mirrored policies. Redis Cluster for caching (replaces in-memory maps). Daily backup test with restore SLA.
02   Integrations Required for Fintech-Grade Platform
🔍 Identity & KYC Verification
Onfido / Sumsub
Biometric Identity Verification
Critical
Government ID scan + biometric liveness check. OCR of passport/driving licence with NFC chip read where available. Returns identity confidence score and fraud flags. Compliant with eIDAS, RBI KYC, FinCEN.
Bureau van Dijk Orbis
Company Registry & Ownership
Critical
Verify company exists in official registry, registered address, incorporation date, active/dissolved status. UBO (Ultimate Beneficial Owner) ownership chain. 400M+ company records globally. Alternative: Companies House API (UK), MCA (India), OpenCorporates.
GLEIF LEI Registry
Legal Entity Identifier
High
Free API lookup by LEI code. Returns legal name, country, registration authority, entity status. Mandatory for financial counterparty identification under MiFID II. Validates the entity is a real, registered legal person.
VAT / GST Validation
VIES (EU) · GSTIN (India) · EIN (US)
High
Verify tax registration numbers are real and currently active. EU: EC VIES API (free). India: GSTN API. US: IRS EIN validation. Prevents shell company onboarding with fabricated tax IDs.
Signicat / DocuSign
eSignature & Digital Identity
Medium
Legally binding digital signature on merchant agreement and Terms & Conditions. eIDAS-qualified signatures for EU. Timestamped and tamper-evident. Replaces manual signing step in current flow.
Email / Phone Verification
Twilio Verify · Mailgun
Medium
OTP via SMS and email during onboarding. Currently the system accepts any email/phone without verification. Twilio Verify covers 150+ countries. Reduces fake registrations by >80%.
🛡️ AML, Sanctions & Fraud Prevention
ComplyAdvantage
Real-time AML & Sanctions Screening
Critical
Screens against 1000+ global watchlists: OFAC SDN, UN, EU, HM Treasury, INTERPOL. PEP and adverse media screening. Real-time alerts on existing merchants when a new sanction is added. Webhooks for ongoing monitoring.
Mastercard MATCH List
Terminated Merchant Database
Critical
Checks if merchant or its principals were previously terminated by any acquirer for fraud, excessive chargebacks, or AML violations. Mandatory check before card acceptance. Failure to check = acquiring bank liability.
LexisNexis Risk Solutions
Identity Risk & Adverse Media
High
Business identity verification + adverse media screening. Detects synthetic identities, identity theft, and shell companies. InstantID for business entity risk scoring. Fraud Shield for device and transaction-level risk.
IP Intelligence + Device Fingerprint
Sift · Kount · MaxMind
High
Detect VPN / Tor / proxy submissions during registration. Device fingerprint ties multiple fake applications to same device. IP geolocation mismatch flagging. Real-time risk score during form submission, not just after submission.
FATF Country Risk Mapping
FATF Grey / Black List API
High
Dynamic list of high-risk and monitored jurisdictions (currently hardcoded rule-based). FATF updates quarterly. Integration ensures risk thresholds auto-update without code deploys. Enhanced due diligence triggers for grey-list countries.
Regulatory Reporting (SAR)
FinCEN · FCA · RBI Automated Filing
Medium
Auto-generate and file Suspicious Activity Reports when screening triggers a match. Currently a human must file manually. Regtech platforms (Actico, Napier) provide automated SAR/CTR filing with audit trail.
🏦 Banking & Payments Verification
Open Banking — Plaid / TrueLayer
Bank Account Verification & Financial Health
High
Verify merchant bank account ownership via Open Banking consent flow. Pull 3–6 month transaction history for financial health assessment. Average balance, revenue trends, and anomaly detection feed directly into the Risk Agent. Plaid covers US/CA; TrueLayer covers EU/UK.
SWIFT BIC / IBAN Validation
Accuity · SWIFT Ref API
High
Validate merchant bank account details (BIC, IBAN, sort code) before onboarding completes. Prevents misdirected payouts. SWIFT Ref API returns bank name, country, branch, and account validity. Accuity also checks OFAC status of the receiving bank.
Experian / Equifax Business
Business Credit Score
Medium
Business credit risk score, payment history, public records (CCJs, insolvency). Used to set initial transaction limits and chargeback thresholds per merchant. Low credit score → higher reserve requirement or delayed settlement.
📬 Notifications, Monitoring & Operations
Twilio / SendGrid
Email & SMS Notifications
High
Currently nothing is sent to the merchant — they must keep the browser open and watch the polling. Required: application received, processing started, approved/rejected with reason, document expiry warnings, periodic re-KYC reminders.
OpenTelemetry + Grafana
Distributed Tracing & Observability
High
Currently no way to trace a request across React → Node.js → RabbitMQ → Java services. OpenTelemetry traces every hop with span IDs. Grafana dashboards for latency, error rates, queue depth. PagerDuty alerting when agents go silent.
Webhook Delivery System
Svix · Custom
Medium
Merchants and partner systems need programmatic status updates. Signed webhook events on application status changes with retry logic, delivery logs, and HMAC verification. Svix provides managed webhook infrastructure with portal for merchant self-service.
03   Process & Workflow Gaps
🔄
Periodic Re-KYC & Ongoing Monitoring
Onboarding is one-time. Regulations (FATF, 4AMLD, RBI) require rescreening existing merchants: annually for low-risk, quarterly for high-risk, immediately on trigger events (ownership change, adverse media alert, new sanction). Currently there is no scheduler, no re-KYC flow, and no trigger mechanism on existing merchants.
Missing
📅
Document Expiry Tracking
Business licenses, tax certificates, and insurance documents expire. The system processes documents through Textract but never extracts or stores expiry dates. Required: parse expiry dates from Textract output, store them, trigger renewal workflows 30/60/90 days before expiry, and auto-suspend merchants whose documents lapse.
Missing
⚖️
Compliance-Ready Decision Explainability
LIME is implemented but the output is internal-only. Regulators (FCA, RBI, CFPB) require that a rejected merchant receives a written explanation of why. The LIME feature importance + KYC findings must be rendered into a human-readable, legally defensible rejection letter with specific grounds cited (not just "risk score = HIGH").
Partial
🏪
Merchant Self-Service Portal
Post-approval merchants need to update business details, add/change bank accounts, upload new documents, view transaction limits, and dispute rejection decisions. Currently no such interface exists — all post-onboarding changes require direct database intervention by an admin.
Missing
📊
SLA Tracking & Regulatory Timelines
Many jurisdictions mandate maximum onboarding timescales (e.g. FCA requires decisions within specific windows). Currently no SLA timer exists — an application can sit in MANUAL_REVIEW indefinitely with no escalation. Required: SLA clock per application, auto-escalation on breach, regulator-ready SLA compliance reports.
Missing
🧪
Zero Automated Tests & No CI/CD
No unit tests, integration tests, or end-to-end tests exist anywhere in the codebase. All deployments are manual shell scripts. In a regulated environment this means no change can be safely deployed and no regression can be caught before it reaches users. Required: Jest for frontend, Supertest for backend APIs, TestContainers for Java services, GitHub Actions CI/CD pipeline.
Missing

05   3-Phase Production Roadmap
1
MVP Hardening
Security & Compliance Basics
~2 months
TLS + secrets manager — Replace .env files with Vault / Secrets Manager. Add TLS on all service ports.
Encrypted PII storage — S3 + SSE-KMS for documents. MongoDB CSFLE for TaxID, name fields. PII masking in logs.
MongoDB replica set — Migrate to Atlas M10+ with 3 nodes, automated backups, and point-in-time recovery.
Email / OTP verification — Twilio Verify for phone OTP, SendGrid for email confirmation during registration.
Onfido or Sumsub integration — Replace rule-based KYC with real government ID + liveness check.
CI/CD + automated tests — GitHub Actions pipeline. Jest (frontend), Supertest (backend), TestContainers (Java).
Maker-checker workflow — 4-eyes approval, role segregation, immutable audit log API.
2
Compliance Layer
AML, Sanctions & Regulatory
~2 months
ComplyAdvantage integration — Real-time OFAC/UN/PEP screening on every application and periodic rescreening of existing merchants.
Mastercard MATCH list check — API call before approving any merchant for card acceptance.
VAT/GST validation — VIES (EU), GSTN (India), IRS EIN (US) to confirm tax IDs are real and active.
Periodic re-KYC scheduler — Quartz/cron jobs for annual/quarterly rescreening. Trigger-based re-KYC on ownership changes.
Document expiry tracking — Extract expiry dates from Textract output, store and alert 30/60/90 days before lapse.
SLA tracking — Timer per application, auto-escalation on breach, compliance reporting dashboard.
Rejection letter generation — LIME output + KYC findings rendered into legally defensible, regulator-ready rejection notices.
3
Scale & Intelligence
Infra, Analytics & Deep Integrations
~3 months
Kubernetes deployment — EKS / GKE with HPA, pod health probes, rolling deploys, and zero-downtime updates.
Redis Cluster — Replace in-memory ConcurrentHashMap and session maps. Shared cache across horizontally scaled instances.
Open Banking (Plaid/TrueLayer) — Bank ownership verification + 3-month transaction history feeding the Risk Agent.
OpenTelemetry + Grafana + PagerDuty — Distributed tracing across all services. Alerting on agent silence, queue depth, and latency spikes.
Weka model retraining pipeline — Automated drift detection. Retrain on new labelled outcomes. A/B test new models before promoting.
Merchant self-service portal — Post-approval profile management, bank account changes, document uploads, limit visibility.
API versioning + SDK — /api/v1/ with changelogs. Partner SDK for embedding onboarding into third-party platforms.
06   What is Already Production-Quality
✅
AI Pipeline Architecture
Genuinely strong — minimal change needed
  • Conditional LLM calls (skip when not needed) — 68% cost saving vs naive approach is industry-leading
  • LangChain4j RAG pipeline with gpt-4o-mini for MCC classification is correctly architected
  • Weka RandomForest + LIME explainer gives ML-based scoring with human-readable feature importance
  • AWS Textract integration with PDF→PNG via Ghostscript is production-grade OCR pipeline
  • Parallel agent execution via RabbitMQ with direct in-process fallback is resilient by design
  • ConcurrentHashMap result cache with confidence threshold is a solid caching strategy (needs Redis to survive restarts)
  • 3-retry + exponential backoff on external service calls is correct fault tolerance
✅
Security Foundations
Solid baseline — needs hardening not rebuilding
  • Helmet.js with CSP, HSTS, X-Frame-Options — most apps don't bother with this at hackathon stage
  • express-rate-limit on both login (10/15min) and API (100/60s) is correct tiering
  • JWT with 8h expiry + bcryptjs rounds:12 — correct implementation
  • requireAuth + requireRole(ADMIN) middleware — proper separation of user and admin endpoints
  • 4-layer duplicate merchant guard is a well-designed anti-fraud layer
  • Multer file type + size restrictions (5MB, PDF/JPG/PNG only) is correct input validation
  • CORS restricted to http://localhost:3000 — not wildcard (*)
✅
Frontend Quality
React patterns used correctly throughout
  • React.lazy + Suspense code splitting on all routes — not common in hackathon projects
  • useMemo for stats/filtered list and React.memo on AgentResultCard — correct performance patterns
  • Exponential backoff polling (3s→30s) — correct approach, prevents hammering the backend
  • touched + validateField progressive validation — errors only after blur, not on first render
  • Debounced duplicate check (600ms) reduces server load during typing
  • Axios JWT interceptor on all /api/* calls — centralised, not duplicated per component
✅
Backend Architecture
Orchestrator pattern is production-scalable
  • OnboardingOrchestrator with separate agents is correctly designed for independent scaling
  • MongoDB compound indexes on (status, name/email/phone) — correct for duplicate-check queries
  • maxPoolSize:10 + minPoolSize:2 connection pool is production-appropriate sizing
  • Promise.all() for parallel Textract calls per document — correct use of concurrency
  • DIAL keep-alive HTTP agent (maxSockets:20) — prevents connection exhaustion on high load
  • TelemetryService per-call token and cost tracking is valuable for cost management
  • ApplicationStorage dual-mode (MongoDB + in-memory Map fallback) is a good resilience pattern
🎯
Bottom Line
The AI pipeline, cost optimisation strategy, and core architecture are genuinely production-quality and require minimal change. The biggest production blockers are sanctions/PEP screening (non-negotiable for any payment acquirer — a single missed hit is a regulatory fine), real identity verification (the current KYC agent validates field formats, not whether a business actually exists), and encrypted PII storage (documents and extracted data are currently stored in plaintext, which is a GDPR and PCI-DSS violation).

Phase 1 (2 months) addresses the blockers and makes the system legally operable. Phase 2 (2 months) adds the compliance layer that banks and regulators require. Phase 3 (3 months) delivers the scale and intelligence that make it a competitive product. The estimated total investment is ~7 months to reach a production-ready state that could be submitted to a regulator for a payment facilitator or acquiring bank licence.
