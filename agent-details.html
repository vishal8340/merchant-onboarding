🪪 KYC Agent
Know Your Customer Verification
Verifies merchant identity and document authenticity using AWS Textract for OCR extraction, cross-validates extracted fields against the application form, detects document quality issues, and calls EPAM AI DIAL (GPT-4o) for a final compliance judgement. Results are published to the event bus for the orchestrator.

Processing Pipeline
🔄 Step-by-step Execution
1
Receive from RabbitMQ
Agent listens on QUEUE_KYC_VERIFICATION. When a new merchant application arrives, it deserialises the full MerchantApplication object including all Textract pre-processed document results already attached by the upload endpoint.
2
Merge Textract Key-Value Pairs
All textractResults[].keyValues maps are merged into a single record. Keys extracted by AWS Textract (e.g. businessName, taxId, email, licenseNumber) are used for cross-validation.
merged = {} textractResults.forEach(r => Object.assign(merged, r.keyValues))
3
Cross-Validate Business Name
Document-extracted business name is compared (case-insensitive substring match) against the application form value. A mismatch deducts 20 pts and escalates to MANUAL_REVIEW.
nameMatch = app.businessName.toLowerCase().includes(doc.businessName.toLowerCase()) ✅ Match → score +10 | ⚠️ Mismatch → score -20, MANUAL_REVIEW
4
Cross-Validate Tax ID
Tax ID from documents is compared character-by-character (ignoring whitespace) with the application tax ID. This is the highest-weight check — a mismatch deducts 30 pts.
docTaxId.replace(/\s/g,'') === appTaxId.replace(/\s/g,'') ✅ Match → score +10 | ⚠️ Mismatch → score -30, MANUAL_REVIEW
5
Document Quality Check
Total word count across all extracted documents is summed. Fewer than 10 words indicates a blank/low-quality scan and triggers a quality warning with -15 pts.
totalWords = textractResults.reduce((s,r) => s + r.wordCount, 0) totalWords < 10 → score -15, quality warning logged
6
Required Document Check
Validates that both BUSINESS_LICENSE and TAX_CERTIFICATE document types are present in the application. Any missing document triggers a -50 pts penalty and FAILED status.
required = ['BUSINESS_LICENSE', 'TAX_CERTIFICATE'] missing = required.filter(d => !uploadedDocTypes.includes(d)) missing.length > 0 → score -50, status = FAILED
7
Field Format Validation
Business name length (min 3 chars), email format (@-check), and Tax ID format XX-XXXXXXX are validated against the form submission.
8
EPAM AI DIAL — KYC Compliance Analysis
The full merchant context (business name, tax ID, email, country, business type, document types, and all extracted KV pairs) is sent to DIAL (GPT-4o). The LLM returns a JSON with kycScore, flags, recommendation (PASS/REVIEW/FAIL), and a summary.
System: "KYC compliance expert — return JSON: kycScore, flags[], recommendation, summary" Input: businessName, taxId, email, country, businessType, documents[], extractedKV Output: { kycScore: 87, flags: [], recommendation: "PASS", summary: "..." }
9
Telemetry + Publish Result
Token counts, latency, model ID, and estimated cost are recorded via TelemetryService. Final result is published to result.kyc for the orchestrator.

🏷️ MCC Agent
Merchant Category Code Classification
Assigns the correct ISO Merchant Category Code (MCC) using a three-layer approach: (1) rule-based lookup from business type, (2) AWS Textract document text scanning for category keywords and risk signals, and (3) RAG-powered classification via the mcc-analyser Java microservice (LangChain4j + GPT-4o + handbook vector store).

Processing Pipeline
🔄 Step-by-step Execution
1
Rule-based MCC Lookup
Business type from the application form is uppercased and matched against a static map. If the mapped MCC is a high-risk code (6051 Crypto or 7995 Gambling), score is immediately reduced by 30 pts and escalated.
RETAIL → 5999 | ECOMMERCE → 5734 | SERVICES → 7299 MANUFACTURING → 5085 | CRYPTO → 6051 ⚠️ | GAMBLING → 7995 ⚠️
2
Textract — High-risk Keyword Scan
All extracted document text (full OCR) is searched for high-risk terms. Any match deducts 40 pts and forces MANUAL_REVIEW regardless of AI confidence.
highRisk = ['gambling','casino','crypto','bitcoin','adult','firearms','tobacco','cannabis'] flagged = highRisk.filter(kw => allText.includes(kw)) flagged.length > 0 → score -40, MANUAL_REVIEW
3
Textract — Category Confirmation
Positive category keywords are searched in document text to confirm the declared business type. A confirmed match adds a positive finding and +5 pts.
RETAIL: ['retail','store','shop','merchandise'] ECOMMERCE: ['e-commerce','ecommerce','online store','digital'] SERVICES: ['services','consulting','advisory','professional'] MANUFACTURING: ['manufacturing','production','factory','industrial']
4
mcc-analyser — RAG Classification (with Retry)
The agent calls the mcc-analyser Java service at localhost:8091. The service uses LangChain4j to perform RAG over an embedded MCC handbook vector store, then calls GPT-4o to select the best MCC code. The agent retries up to 2 times on failure (exponential backoff).
POST http://localhost:8091/api/v1/onboarding/classify Body: { businessName, businessType, businessDescription, documents[] } Response: { mccCode, confidence, reasoning, detectedRisks[], handbookCitation }
5
Score Override from AI Confidence
When the mcc-analyser returns a valid (non-fallback) result, the AI confidence score directly replaces the rule-based score. If confidence ≥ 0.65, status stays PASSED. Below 0.65 → MANUAL_REVIEW.
score = Math.round(confidence * 100) // e.g. 0.87 → score=87 if (score < 65 && status === PASSED) status = MANUAL_REVIEW_REQUIRED
6
EPAM AI DIAL — Secondary MCC Validation
A secondary DIAL call provides an independent MCC opinion based on business name, type, country, email, and Textract KV pairs. Used for audit trail and override suggestions. Results stored in dialResponse.
🏗️ mcc-analyser Architecture
The mcc-analyser is a standalone Spring Boot microservice that exposes a REST endpoint. Internally it uses a full RAG pipeline:
A
Document Embedding
The MCC handbook (October 2025 edition) is chunked and embedded into an in-memory vector store using LangChain4j + OpenAI embeddings.
B
Semantic Retrieval
The merchant business description is used as a query to retrieve the top-k most relevant MCC handbook sections from the vector store.
C
GPT-4o Classification
Retrieved handbook context + merchant data is sent to GPT-4o which selects the best MCC code, provides confidence (0–1), reasoning, detected risks, and a handbook citation.
D
RabbitMQ Integration
The service also consumes tasks from RabbitMQ queue mcc.tasks for async processing (used by the test endpoint).

Feature Extraction from Documents
📄 How Risk Features Are Extracted from Textract
1
Location Extraction
Searches KV pairs for keys matching location|address|city|state|country|region. Falls back to application's country field.
locationKey = KV keys matching /location|address|city|state|country|region/i location = allKV[locationKey].split(',')[0] // first part before comma
2
Years in Business Extraction
Searches KV keys for incorporation/registration/license dates. Extracts the 4-digit year and computes age. Also scans raw text for patterns like "incorporated 2018". Defaults to 3 years if not found.
dateKey matches: /date|incorporated|registration date|license date|issue date|valid from/i yearMatch = value.match(/\b(19|20)\d{2}\b/) yearsInBusiness = currentYear - extractedYear // Text fallback allText.match(/(?:incorporated|established|registered|founded)[^\d]*\b(19...|20..)\b/)
3
Transaction Volume Extraction
KV pairs with keys matching volume|revenue|turnover|sales|transaction are parsed for numeric values. Defaults to $50,000/month.
4
Chargeback Rate Extraction
Searches for chargeback|dispute|refund KV pairs. Handles both decimal (0.002) and percentage (0.20%) formats automatically.
val = parseFloat(numMatch[0]) chargebackRate = (raw.includes('%') || val > 1) ? val / 100 : val // e.g. "0.20%" → 0.002 | "0.002" → 0.002 | "1.00%" → 0.01
5
Compliance Score Extraction (Priority Order)
Priority 1: Explicit KV pair — keys matching compliance score|compliance rating|aml score → uses raw value.

Priority 2: Text-signal boosted formula — scans document body for positive compliance phrases and accumulates bonus points on top of base score.
// Priority 1 — explicit KV complianceScore = (val > 10) ? val : val * 10 // handles 0-10 and 0-100 scales // Priority 2 — text signal boosts (base = 50 + docs*5 + website?10:0) +10 "tax clearance" or "tax compliance certificate" +8 "certificate of incorporation" or "duly registered" +8 "good standing" or "in good standing" +10 "aml compliant" or "kyc compliant" or "pci" +5 "licensed" or "business license" +5 "no criminal" or "clear record" +8 KV key matches /clearance|certified|license|permit|registration/
smart-risk-scoring Pipeline (Java ML Service)
🔬 Internal ML + LLM Pipeline (Port 8080)
0
LLM Fraud Detection + Country Risk (Single GPT-4o Call)
A single LLM call analyses 8 fraud checks and geographic risk simultaneously. Returns structured JSON with fraud signals and country risk score (0–100). If LLM fails, falls back to rule-based fraud detection.
Fraud checks: HIGH_CHARGEBACK, BUST_OUT, CNP_RISK, AML_FLAG, SHELL_COMPANY, INDUSTRY_RISK, STRUCTURING, VELOCITY_ANOMALY Country: riskLevel, score, regulatoryNote, recommendations[]
1
Feature Encoding (10 features → Weka ML)
10 features are encoded into a double[] for the RandomForest model. Business type and location are ordinal-encoded from training data distributions.
features[0] = businessType (encoded ordinal) features[1] = transactionVolume features[2] = location (encoded ordinal) features[3] = chargebackRate features[4] = yearsInBusiness features[5] = averageTransactionSize features[6] = fraudFlag (0 or 1 — from LLM step) features[7] = complianceScore features[8] = fraudSeverity (0=NONE → 4=CRITICAL) features[9] = countryRiskScore (0–100 from LLM)
2
Weka RandomForest Prediction
The trained model (risk_model.ser) predicts the risk class and returns probability distribution across Low/Medium/High risk labels.
riskLabel = inference.predictFromFeatures(features) // "Low"|"Medium"|"High" probabilities = inference.predictProbabilities(features) // [pLow, pMed, pHigh]
3
LIME Explainability
LIME perturbs the input features and fits a local linear model to explain which features most influenced the prediction. Top-5 feature contributions (with weight, direction, impact level) are returned.
4
Composite Risk Score Formula
A 0–100 raw risk score is computed from the probability, chargeback rate, compliance score, fraud signals, volume, and business age. This score is then inverted (100 − riskScore) to produce the safety score shown in the UI.
modelScore = probHigh * 50 // 0–50 pts chargebackScore = min(cbRate/0.15, 1) * 15 // 0–15 pts complianceScore = max(0,(100-compliance)/100) * 15 // 0–15 pts fraudScore = min(fraudSignals, 4) * 2.5 // 0–10 pts volumeScore = min(volume/200000, 1) * 5 // 0–5 pts ageScore = max(0,(5-years)/5) * 5 // 0–5 pts total = sum (0–100, clamped) uiScore = 100 - total // higher = safer
5
LLM Reports (Single GPT-4o Call — 7 Reports)
All 7 reports are generated in a single LLM call using delimiter-separated output. Max 4,000 tokens.
===ANALYST_REPORT=== 200-300 words risk assessment ===COMPLIANCE_REPORT=== Full regulatory analysis (BSA/AML, PCI-DSS) ===SALES_REPORT=== <150 words for sales rep ===MERCHANT_NOTIFICATION=== <100 words friendly merchant message ===EXECUTIVE_BRIEF=== <50 words C-suite dashboard ===ANOMALY_DESCRIPTION=== 100-150 words fraud analyst view ===OVERRIDE_SUGGESTION=== OVERRIDE_RECOMMENDED or NO_OVERRIDE + reason ===CONSISTENCY_SCORE=== { score, llmVerdict, mlVerdict, agrees, reason }

Aggregation & Decision Logic
🧮 Decision Rules (makeDecision)
R1
Any agent FAILED → REJECTED
If KYC, MCC, or Risk agent returns status=FAILED, the final decision is REJECTED regardless of other agent scores.
results.some(r => r.status === 'FAILED') → REJECTED
R2
Any agent MANUAL_REVIEW → MANUAL_REVIEW
If any agent flags for human review (and none failed), the application goes to manual review queue.
results.some(r => r.status === 'MANUAL_REVIEW_REQUIRED') → MANUAL_REVIEW
R3
Average Score < 60 → MANUAL_REVIEW
Even if all agents pass individually, a low average score across all three agents triggers manual review.
avgScore = (kycScore + mccScore + riskScore) / 3 avgScore < 60 → MANUAL_REVIEW
R4
All PASSED + avg ≥ 60 → APPROVED
All three agents passed with sufficient average score. Application is auto-approved and merchant is notified.
